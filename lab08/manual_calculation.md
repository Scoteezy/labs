# Ручная проверка NDCG@3 и Recall@3

Запрос **V14** «саксофон для афиши с воздухом и паузой». По qrels релевантны P003 (2) и P004 (1). Ранжировщик вернул P015 (0), P027 (0), P003 (2). На всех трёх позициях совпала только форма «для». [Фактическая выдача](results/rankings.csv)

- Веса релевантности на позициях — `0, 0, 3`. `DCG@3 = 0/log₂(2) + 0/log₂(3) + 3/log₂(4) = 1,5`.
- В идеальном порядке оценки `2, 1, 0`. `IDCG@3 = 3 + 1/log₂(3) ≈ 3,630930`.
- `NDCG@3 = 1,5 / 3,630930 ≈ 0,413117`. Найдена только P003 из двух релевантных карточек, поэтому `Recall@3 = 1/2 = 0,5`.

| Сценарий | Оценки по позициям | DCG@3 | NDCG@3 вручную / код | Recall@3 вручную / код |
|---|---|---:|---:|---:|
| Реальный V14 | 0, 0, 2 | 1,500000 | 0,413117 / 0,413117 | 0,5 / 0,5 |
| Идеальный для V14 | 2, 1, 0 | 3,630930 | 1 / 1 | 1 / 1 |
| Перестановка для V14 | 1, 2, 0 | 2,892789 | 0,796708 / 0,796708 | 1 / 1 |
| Реальный V13, пустая выдача | — | 0 | 0 / 0 | 0 / 0 |

При перестановке `DCG@3 = 1 + 3/log₂(3)`. Recall сохраняется, так как в обоих порядках найдены обе релевантные карточки. У V13 релевантные карточки те же, пустой список даёт ноль в числителе обеих метрик.
