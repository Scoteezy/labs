# Матрица выбора архитектуры

## Архитектурный вопрос

Как искать до трёх афиш по короткому русскоязычному брифу локально, чтобы показать дизайнеру происхождение каждого референса и сохранить поиск при отказе улучшения?

Все варианты решают текстовый поиск по одним описаниям набора 2.0. В рабочем каталоге 36 синтетических карточек. Контрольный сценарий использует 12 запросов, 12 карточек validation и 144 пары с оценками релевантности. В A и B веса IDF вычисляются на 12 описаниях train. В C предлагается готовый энкодер без дообучения и точный косинусный поиск по 12 dense-векторам тех же описаний. Для оценки во всех вариантах нужны одинаковые оценки релевантности, правило top-3 и порядок по ID при равном балле. Варианты различаются представлением текста. [Набор и разбиение](../lab06/README.md) · [Метрики и пороги](../lab08/metric_spec.md)

## Обязательные условия

1. Поиск и хранение локальные, без API-ключа, платных вызовов и пересылки брифа или каталога сервису.
2. До выдачи и при получении изображения доступны только карточки с `demo_allowed` и непустым `source`. Это условие действует для штатного и резервного режимов.
3. Дизайнер принимает окончательное решение. Исправление стиля поступает на проверку архивариусу.
4. Запуск воспроизводим с фиксированными версиями каталога и параметров. Недоступность улучшения, неверный вход и пустая выдача различимы.

A и B выполняют локальный поиск в эксперименте ЛР 9, где проверены выдача и допуск. Действия дизайнера, статусы и журнал предусмотрены общей архитектурой. C может пройти отбор после проверки офлайн-запуска, лицензий зависимостей и общего фильтра. Разрешение к внедрению требует выполнения всех условий. ## Шкала и оценки

Для порядковых оценок 3 означает преимущество при текущем масштабе, 2 — приемлемый компромисс при выполнении допущений, 1 — существенное ограничение. Значения по критериям приведены ниже. Все оценки в баллах — учебная оценка команды для каталога 2.0, локального CPU и текущих компетенций. Измерения сохраняются в исходных единицах. Без прогона измеряемая величина остаётся неизвестной.

| Критерий | A · TF-IDF | B · TF-IDF и словарь 1.0 | C · Локальный multilingual-e5-small |
|---|---|---|---|
| Качество на validation, NDCG@3 / Recall@3 | 0,238525 / 0,208333 | 0,857373 / 0,875000 | Не измерено |
| Качество на test, NDCG@3 / Recall@3 | Не измерено в ЛР 9 | 0,355740 / 0,333333 | Не измерено |
| Данные для индексирования | **3** · текст описаний и train-IDF | **2** · описания, train-IDF и проверяемый словарь | **3** · те же описания, ручной словарь не требуется |
| Задержка поискового ядра, p50 / p95, мс | 0,007250 / 0,011333 | 0,008292 / 0,012459 | Не измерена. Нужен замер CPU-инференса |
| Прямые расходы и ресурсы | **3** · стандартная библиотека, 0 за API | **3** · стандартная библиотека, 0 за API | **2** · 0 за API в офлайн-схеме, дополнительные веса и среда выполнения |
| Лицензии и права | **3** · происхождение каталога зафиксировано, внешних весов нет | **3** · те же условия и локальный словарь ЛР 9 | **2** · MIT по карточке модели, лицензии выбранного стека предстоит проверить |
| Объяснимость | **3** · совпавшие токены и оценки | **3** · совпавшие токены и правила замены | **1** · сходство векторов без объяснения по словам |
| Поддерживаемость | **3** · базовый модуль и артефакт IDF | **2** · словарь, контроль версий и пересчёт IDF | **1** · модель, токенизатор, среда и переиндексация |
| Риски в текущей alpha | **2** · слабое покрытие синонимов, известная точка отсчёта | **1** · заметный разрыв validation и test, возможны ложные замены | **1** · неизвестны качество на брифах, ресурсы и поведение при смене версии |

- **Данные.** 3 — те же тексты, без дополнительной ручной разметки или правил. 2 — нужны проверяемые ручные правила. 1 — нужен новый размеченный корпус. Готовые веса C учитываются в ресурсах и лицензиях.
- **Расходы.** 3 — текущий CPU и стандартная библиотека. 2 — предположительно тот же CPU, дополнительные веса и зависимости. 1 — обязательная покупка оборудования или оплачиваемые запросы. Время сотрудников, оборудование и энергопотребление в денежном выражении не оценивались.
- **Лицензии.** 3 — известные исходные условия без новой внешней модели. 2 — лицензия модели указана, проверка комплекта зависимостей предстоит. 1 — обнаружен блокирующий запрет или неясные права на обязательный ресурс. Допуск реальных афиш потребует отдельной проверки архивариусом.
- **Объяснимость.** 3 — можно показать совпавшие слова и применённые правила. 2 — нужна дополнительная диагностика. 1 — доступно лишь численное сходство.
- **Поддерживаемость.** 3 — один режим с существующим пайплайном. 2 — дополнительный словарь и пересборка текстовых весов. 1 — отдельный стек с версионированием модели и векторов.
- **Риски.** 3 — основные риски контролируются и перенос качества подтверждён. 2 — наблюдаемое ограничение с понятным способом диагностики. 1 — существенный риск переноса или пока непроверенная пригодность.
- **Качество и задержка.** NDCG@3 сопоставляется с ориентиром 0,70, Recall@3 — с зафиксированным baseline на сопоставимой выборке. Задержка ядра указывается в миллисекундах. Ориентир ЛР 3 в 10 секунд относится к полному пути от отправки запроса до получения ответа.

На validation у A было 0 выдач без допуска из 16 позиций, у B — 0 из 31. На test у B — 0 из 27. Контроль с `unknown` пройден для A и B. Словарь подбирался по наблюдениям на validation. Test даёт абсолютную оценку выбранного режима B на другой группе, а относительный эффект на этой группе остаётся неизвестным. [Сравнение ЛР 9](../lab09/comparison.md) · [Результат test](../lab09/results/test_summary.json)

Замер выполнен на Apple M5 Pro, macOS arm64, CPython 3.9.6. После 20 циклов прогрева выполнено 100 циклов по 12 запросов, по 1 200 замеров на режим. Индексы загружены в память. Измерены токенизация, жанровые замены в B, векторизация запроса и косинусный top-3. Проверка допуска при сборке индекса, чтение файлов, HTTP, интерфейс и сериализация карточек находятся за пределами этого замера. Время зависит от машины и текущей нагрузки. ## Выбор

A используется в учебной alpha как прозрачная точка отсчёта и способ продолжить поиск при отказе B. Его NDCG@3 на validation тоже ниже 0,70, поэтому обе ветки имеют статус учебной проверки. B остаётся кандидатом для контролируемого эксперимента. На полноценный выпуск основного режима влияют перенос качества и проверки обязательных условий. Новая инфраструктура C потребует отдельного подтверждения пользы. [Решение ADR-01](architecture_decision.md)
