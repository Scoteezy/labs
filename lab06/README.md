# Лабораторная работа 6. Разметка и подготовка пар изображений

Эта работа продолжает проект «Выявление искажений товара в рекламных изображениях после генерации». Версия набора 1.0 состоит из контролируемо созданных пар исходной и изменённой упаковки. Она предназначена для проверки воспроизводимого пути подготовки и не заменяет набор реальных результатов генерации.

## Метка и подготовка

Метка `1` означает критическое изменение текста, логотипа или формы товара. Метка `0` означает, что эти элементы сохранены. Изменение фона, освещения и позиции товара допускается, если упаковка не повреждена. Пограничные случаи направляются на ручную проверку. Полные определения, примеры и порядок независимой разметки приведены в [инструкции](annotation_guideline.md). [Журнал решений](decision_log.md) фиксирует границы набора и порядок работы со спорными случаями.

Пары группируются по `family_id`. Всё семейство попадает только в одну часть train, validation или test. Это защищает оценку от утечки близких вариантов одной упаковки.

## Воспроизведение

Выполняйте из корня репозитория. Зависимости зафиксированы в [requirements.txt](../lab04/requirements.txt).

```sh
python -m pip install -r lab04/requirements.txt
python -m lab04.generate --check
python -m lab06.prepare --check
python -m unittest lab06.test_prepare -v
```

Команда подготовки проверяет обязательные поля, права, тип метки, связь метки с типом дефекта, уникальность пары, границы прямоугольников, RGB-формат, SHA-256 файлов, отсутствие пересечения товаров между split и наличие обоих классов в каждой части. Для повторной записи запустите `python -m lab06.prepare`. Она создаёт [prepared.json](data/prepared.json) и [summary.json](data/summary.json).

`prepare_pair` принимает две RGB-иллюстрации Pillow и два прямоугольника `[left, top, right, bottom]`. Он обрезает области товара, масштабирует их до 128×128, переводит в яркость BT.709 и возвращает два массива `float32` в диапазоне [0, 1]. Параметры не обучаются на данных, поэтому подготовка не использует информацию из test. Эта функция является единственной подготовкой изображений для ЛР 7, 9 и 11.

## Контроль разметки

Отдельного независимого разметчика в пилоте не было. В документации это ограничение оставлено явным. Альтернативная процедура — [визуальный просмотр ассистентом 12 примеров](data/visual_pilot.csv) со скрытым `defect_type`, контроль правил контролируемой генерации, файловых отпечатков и рамок товара. Такая проверка показывает целостность и воспроизводимость учебного набора. Для реальных рекламных результатов необходима независимая разметка или экспертная ревизия.

Статистика версии и результаты альтернативного контроля приводятся в [annotation_results.md](annotation_results.md), а Data Card обновлена в [data_card.md](data_card.md).
