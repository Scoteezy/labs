# Лабораторная работа 12. Знания и контроль дизайнера

Проект «Выявление искажений товара в рекламных изображениях после генерации». API соединяет детектор ЛР 11 с правилами применимости и решением дизайнера. Пользователь выбирает одну из 192 пар пилота, подтверждает условия сравнения и получает оценку со ссылкой на источник. Действия accept, reject, correct и escalate изменяют состояние проверки и сохраняются в SQLite.

## Запуск

Из корня репозитория с Python 3.12 и зависимостями ЛР 4.

```sh
python -m pip install -r lab04/requirements.txt
python -m lab12.server
```

Сервер слушает 127.0.0.1:8766. Стандартное хранилище — `lab12/runtime/review.sqlite`. Путь можно задать через `--db PATH`, порт через `--port`. Для остановки нажмите Ctrl+C.

В другом терминале отправьте пару с ложной тревогой из-за затемнения.

```sh
curl -sS http://127.0.0.1:8766/inspect \
  -H 'Content-Type: application/json' \
  --data-binary '{"record_id":"PAIR019_04","context":{"same_product":true,"frontal_view":true,"label_visible":true,"regions_aligned":true}}'
```

Ожидается `assessment=suspected_distortion`, score 0,045095841432 и `review_status=awaiting_designer`. После просмотра кадров можно отправить исправление с возвращённым inspection_id. Конкретная последовательность приведена в [примерах](correction_and_escalation.md).

## Проверка

```sh
python -m lab12.verify
python -m unittest lab12.test_service -v
```

Первая команда выполняет 19 HTTP-сценариев, открывает хранилище повторно и проверяет четыре сохранённых события, защиту от дублирования и хеши исходных данных. Она использует временную базу. Реальный журнал рабочей сессии хранится по пути из `--db`.

[Фактический протокол](results/workflow_examples.json) содержит полные запросы, ожидания, ответы и состояние после повторного открытия. При сверке исключается только фактическое время события `created_at`. Проверяется, что оно имеет часовой пояс. Оценки, статусы, идентификаторы и все остальные поля сверяются.
