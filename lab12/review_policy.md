# Рассмотрение обратной связи

Дизайнер просматривает два изображения и сопоставляет надпись, логотип и контур по инструкции ЛР 6. Решение accept оставляет кадр в текущем учебном сценарии, reject отправляет его на доработку. Если сигнал модели расходится с наблюдением, дизайнер предлагает correct с меткой, типом изменения и основанием. Если оснований недостаточно, используется escalate.

События correct и escalate имеют статус pending_review. Ответственный за разметку получает ID проверки, открывает исходную пару и журнал, проверяет применимость инструкции и записывает решение принять или отклонить с причиной. В индивидуальном проекте разработчик может выполнять эту роль, явно указав совмещение ролей. Независимая экспертная оценка остаётся отдельной процедурой.

Интерфейс экспертного утверждения для этого выпуска описан процедурно. Очередь можно просмотреть через GET /feedback. До её рассмотрения release_allowed=false. Чтобы оформить изменение, ответственный сохраняет отдельный протокол рассмотрения со ссылкой на event_id и исходную версию.

Принятая правка входит в новый выпуск разметки после проверки источника, сохранения групп family_id, пересчёта статистики и повторного эксперимента на зафиксированных условиях. Затем выпускается новая версия модели и конфигурации. Отклонённое предложение остаётся в журнале вместе с причиной. Сырые события хранятся как обратная связь.

SQLite обеспечивает транзакционную запись и уникальность event_id и inspection_id. Время события записывается в UTC. Число повторов одного запроса не увеличивает число событий. Одновременные решения по одной проверке дают одно принятое действие и конфликт второго.

Роль designer_demo приходит в JSON. Для localhost это демонстрация маршрута ответственности. Аутентификация пользователей, удалённый доступ и экспертное утверждение в API в текущую версию не входят. Поле note предназначено для краткого описания дефекта без имён, контактов и секретов. Картинки и Base64 в БД не записываются.

Набор содержит собственные контролируемые синтетические макеты. Пользовательские условия видимости и сопоставимости имеют статус заявления пользователя, которое следует проверить на кадрах. Оценки пилота не подтверждают пригодность для реальной рекламы.
