# Исправление и эскалация на парах упаковки

Полный протокол получен запуском python -m lab12.verify. Он содержит запросы, ответы и состояние после повторного открытия SQLite. [Машиночитаемые результаты](results/workflow_examples.json)

## Исправление ложной тревоги

PAIR019_04 имеет сохранённую упаковку при пониженной яркости. SSIM-разность 0,045095841432 превышает порог 0,017705861976, поэтому детектор возвращает suspected_distortion. После просмотра исходника и варианта дизайнер предлагает метку 0.

```json
{
  "event_id": "E_correct_01",
  "inspection_id": "I_418c7bb927053c980bb484ac",
  "actor": "designer_demo",
  "action": "correct",
  "proposed_label": 0,
  "defect_type": "none",
  "note": "Затемнение кадра. Текст, логотип и форма сохранены."
}
```

Фактический ответ имеет status=pending_review и review_status=awaiting_expert. В нём model_updated=false и dataset_updated=false. GET проверки сохраняет первоначальные score и assessment и показывает предложение дизайнера. Повторный POST /inspect также показывает awaiting_expert. Дизайнерская метка находится в отдельном событии до решения ответственного.

Значение inspection_id выше относится к опубликованным версиям данных, знаний и модели. При запуске другого выпуска используйте ID, полученный от POST /inspect.

## Эскалация при неизвестной видимости

Для PAIR002_01 в запросе задано label_visible=false. Это контролируемый сценарий неподтверждённого условия. На исходных изображениях пилота этикетка присутствует. Запрос проверяет маршрутизацию по ответу пользователя.

Слой знаний возвращает assessment=manual_review, machine_result=null, причину label_visibility_not_confirmed и awaiting_expert. Попытка accept получает 409 expert_review_required. Действие escalate с основанием записывается как pending_review. Ответственный должен получить подходящий кадр или уточнить условия и оформить результат проверки.

## Принятие и отказ

На PAIR001_01 изменение фона даёт passed. После accept состояние становится designer_accepted. На PAIR001_08 изменена надпись, ответ suspected_distortion. После reject состояние становится designer_rejected, что означает направление кадра на доработку.

Из 19 HTTP-шагов четыре создают события. Повтор accept с тем же event_id возвращает уже записанный ответ. Новое содержимое с использованным ID отклоняется. Хеши prepared.json, решения ЛР 9, настроек ЛР 11 и knowledge.json после всех действий совпали с исходными.
