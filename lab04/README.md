# Лабораторная работа 4. Реестр данных и Data Card

Проект «Выявление искажений косметической упаковки в рекламных изображениях после генерации». Эта работа фиксирует пилотный набор пар «исходник товара - вариант рекламы» до обучения и выбора модели.

Набор v1.0 содержит 192 PNG-пары для 24 процедурно нарисованных дизайнов упаковки, объединённых в 12 семейств. Изображения и этикетки сгенерированы этим репозиторием на Pillow. Это контролируемый синтетический пилот, а не коллекция реальных результатов генеративного редактирования. Поэтому он проверяет воспроизводимость пайплайна и логику split, а выводы о реальных генераторах или товарах делать по нему нельзя.

## Воспроизведение

Из корня репозитория с Python 3.12:

    python -m pip install -r lab04/requirements.txt
    python -m lab04.generate
    python -m lab04.generate --check

Первая команда генератора перезаписывает только lab04/data, source_registry.csv и split.json детерминированными данными с seed 20261124. Проверка сверяет схему, баланс, групповой split и SHA-256 всех файлов выпуска.

## Структура и split

Единица анализа - пара. label=1 означает критичное искажение одного из трёх элементов товара: текста, логотипа или формы. label=0 означает, что текст, логотип и форма сохранены, хотя фон, яркость и небольшое положение товара меняются.

В каждом дизайне есть четыре отрицательных и четыре положительных случая. Фоновые и световые изменения встречаются в обоих классах, поэтому признак фона сам по себе не должен определять метку. В каждом семействе находятся два производных дизайна. Семейства целиком разделены между train, validation и test, чтобы варианты одного дизайна не сделали оценку легче.

Набор включает 96 пар класса 0 и 96 пар класса 1. Типы меток распределены так: none - 96, text - 48, logo - 24, shape - 24. Реальные числа проверяются командой --check.

## Граница применения

Первая alpha-версия ориентирована на один примерно фронтальный товар с видимой этикеткой. В кадре можно менять фон, свет и положение. Сильный поворот, закрытие товара, размытие и отсутствие видимой этикетки направляются на ручную проверку в следующих работах. Модель не принимает решение о допуске рекламы к публикации. Дизайнер проверяет подозрительное изменение и принимает итоговое решение.
